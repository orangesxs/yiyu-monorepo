# 后台管理 · 需求设计

> 模块路径:`/admin`,入口:头像下拉「后台管理」(**仅管理员可见**);**平台级管理模块而非子应用**,身份色石板灰 `--app-admin`
> 涉及代码:`src/modules/admin/` —— `types.ts`(SystemUser / AdminLog / LogModule / LogAction)、`mock/users.ts`、`mock/logs.ts`、`stores/admin.ts`、`routes.ts`(`adminRoutes`)、`views/AdminDashboard.vue` / `views/AdminUsers.vue` / `views/AdminLogs.vue`
> 联动改造:`shared/types/common.ts`(User 增 `role`)、`shared/stores/user.ts`(`isAdmin`)、`shared/types/router.d.ts`(`app` 加 `'admin'`、新增 `requiresAdmin`)、`router/index.ts`、`shared/layouts/AppShellLayout.vue`(admin 菜单组 + 头像下拉)、`shared/layouts/PortalLayout.vue`(头像下拉)、`styles/tokens.css`(`--app-admin`)。**广场个人名片的「后台管理 →」链接已随名片移除(2026-09-10)**
> 现状:**已实现**(2026-09-09;2026-09-10 随记事本/好友/名片移除同步精简),`pnpm type-check` 通过。文中按当前实现描述,与记账本/个人中心两份文档的体例一致。

## 1. 产品定位

后台管理是一隅的**平台级管理模块**(与个人中心同级,而非与记账本并列的生活子应用):从系统运维视角管"人、事、日志"——用户目录、操作审计、资源概览。个人中心是**用户视角**(我是谁),后台管理是**运维视角**(系统里有哪些人、发生过什么、资源规模如何),两者互补、共享同一批底层数据的只读视图。**后台概览只统计"系统资源"(用户/账本/日志),不展示流水笔数与收支金额等业务数据**——那是记账本自己的报表要管的事。

mock 阶段**登录即管理员**:任何用户名登录均写入 `role: 'admin'`,无需账号密码校验;真实角色体系(管理员审批、超管、权限粒度)列入未来规划。

## 2. 角色与权限

### 2.1 角色定义

| 字段/类型 | 说明 |
|---|---|
| `UserRole` | `'admin' \| 'user'`,定义于 `shared/types/common.ts` |
| `User.role?` | 可选字段,**兼容旧登录态**(localStorage `yiyu-user` 无 role 时按非 admin 处理,不会凭空获得后台入口) |
| `userStore.isAdmin` | computed:`user.value?.role === 'admin'`,全站唯一的"是否管理员"判定来源 |
| `login()` | mock 简化:固定写 `role: 'admin'`(真实角色体系见 §7) |

### 2.2 路由守卫

- `RouteMeta` 新增 `requiresAdmin?: boolean`;`app` 联合类型扩展为 `'ledger' | 'profile' | 'admin'`。
- 守卫顺序(router/index.ts):先 `requiresAuth`(未登录去登录页),再 `requiresAdmin`(非 admin 弹 `ElMessage.warning('该区域仅管理员可见')` 并重定向广场 `/`)。
- admin 模块全部路由 `requiresAuth: true` + `requiresAdmin: true`。
- 守卫里不引 Element Plus 的重量组件亦可(仅用 ElMessage),保持 router 层轻量。

## 3. 入口设计

个人中心"不进应用卡栅格"的策略同样适用于后台管理——应用卡区保持记账本一张生活应用卡不变,管理后台不是"生活应用",入口藏在"我"的身份里:

- **头像下拉**(PortalLayout 与 AppShellLayout 两处):「个人中心」与「退出登录」之间插入「后台管理」项(`v-if="isAdmin"`),图标 `Setting`,跳 `/admin/dashboard`。
- **广场个人名片(me-card)底部的「后台管理 →」链接已随名片移除(2026-09-10)**,后台入口仅剩头像下拉一处。

## 4. 领域模型

### 4.1 系统用户(SystemUser)

| 字段 | 说明 |
|---|---|
| `id` | 用户 id,与账本成员历史同一 ID 空间(u1 安 ~ u7);好友目录已随好友功能移除,当前与 profile 无引用关系 |
| `username` / `name` / `avatar` | 登录名 / 昵称 / emoji 头像(与 profile mock 的姓名头像一致) |
| `role` | `UserRole`:'admin' 管理员 / 'user' 普通用户 |
| `status` | `UserStatus`:'active' 正常 / 'disabled' 停用 |
| `registeredAt` | 注册日期 `YYYY-MM-DD` |
| `lastActiveAt` | 最近活跃 `YYYY-MM-DD HH:mm` |

- mock 预置 **u1~u7 全量目录**:u1 安(admin,即当前登录人)、u2 小林、u3 妈妈、u4 表妹、u5 老周(**预置停用**,供状态筛选演示)、u6 阿俊、u7 阿泽。
- **已知简化**:SystemUser 与 `modules/profile` 的档案是**两份独立 mock 数据**(登录人 u1 的姓名/头像对齐但互不引用)——接后端时归一为单一用户表;文档不夸大为"全站用户中心"。
- **u1(当前登录人)不可自改角色/停用自己**(与 Books.vue "admin 不可改自己"同一保护逻辑),操作按钮禁用。

### 4.2 系统日志(AdminLog)

| 字段 | 说明 |
|---|---|
| `id` | `log-` 前缀 + 序号 |
| `time` | `YYYY-MM-DD HH:mm`,列表按此倒序 |
| `moduleId` | `LogModule`:`'auth' \| 'ledger' \| 'profile' \| 'admin'` |
| `action` | `LogAction`:`'login' \| 'create' \| 'update' \| 'delete' \| 'security'` |
| `operatorId` | 操作人 id(u1~u7) |
| `summary` | 一句话内容,≤40 字 |

- `moduleLabels`(认证/记账本/个人中心/管理后台)与 `actionLabels`(登录/新增/更新/删除/安全)常量定义于 `modules/admin/types.ts`,仿 profile 的 `sourceLabels`。
- mock 预置约 **21 条**,覆盖 2026-09-01 ~ 09-07(mockToday)、多位操作人、全部模块与类型——保证三个筛选维度与概览页 7 日趋势图都有数据。**纯 mock 预置**,不做会话内实时记录(侵入各模块 store,改动面大,列入未来规划)。

### 4.3 资源概览口径

概览页统计**不做 admin 自己的资源快照**,而是跨模块只读消费各 store(遵循 PortalHome 先例,只 import store、不 import 别人的 mock):

- 用户数 ← admin store;账本数 ← ledger store;日志数 ← admin store。**不消费流水笔数与收支金额**——后台是运维视角,业务数据留在记账本报表里(2026-09-10 精简,流水/本月支出/本月收入三张统计卡已移除)。
- 时间口径统一锚定 `mockToday`(2026-09-07),不得用 `new Date()`。

## 5. 页面设计

壳层菜单顺序:**数据概览 → 用户管理 → 系统日志**。壳层 admin 组:名称「管理后台」、副标题「守好一隅的每个角落」、徽标 🛠️、组色 `var(--app-admin)`;菜单图标:概览 `Odometer` / 用户 `UserFilled` / 日志 `List`。

### 5.1 数据概览(`/admin/dashboard`,默认页)

`/admin` redirect 至此。meta `{ app: 'admin', title: '数据概览', requiresAuth: true, requiresAdmin: true }`。

- **统计卡行(2 卡)**:注册用户 / 账本(数量,中性色,数字加 `.num`)。流水与收支金额卡已移除(2026-09-10,见 §4.3)。
- **双图表区**:左「近 7 日操作趋势」柱状图(由日志按日聚合:09-01 ~ 09-07 七根柱,身份色 `--app-admin`);右「数据分布」环形图(账本/用户/日志三类计数)。ECharts 按 Reports.vue 模式在组件顶部按需 `use()` 注册。
- **最近操作**:最新 8 条日志行(时间 + 操作人 + 模块 tag + 摘要),右上「查看全部 →」跳 `/admin/logs`。

### 5.2 用户管理(`/admin/users`)

- **统计行**:用户总数 / 管理员数 / 正常 / 停用(数字 `.num`)。
- **筛选区**:关键词搜索(昵称/用户名,大小写不敏感)+ 角色 el-select(全部/管理员/普通)+ 状态 el-select(全部/正常/停用)。
- **用户卡列表**(自绘卡片行,项目无 ElTable 惯例):头像 emoji、昵称、@username、角色 tag(管理员=身份色/普通=info)、状态 tag(正常=success/停用=info)、注册日期、最近活跃时间;行尾操作:
  - **设为管理员 ↔ 降为普通**:ElMessageBox 确认(升权文案提示风险)后调 store;u1 自己禁用;
  - **停用 ↔ 启用**:ElMessageBox 确认(停用文案注明"mock 仅标记状态,不阻断其 mock 行为");u1 自己禁用。
- **新增用户弹窗**(el-dialog 420px,label-position top):头像 emoji 宫格 12 选 1(自绘 button,显式 `type="button"`——见个人中心文档 §6 的 form 内裸 button 教训)、昵称必填 ≤12(show-word-limit)、用户名必填且**查重**(与现有 username 重复时报"该用户名已存在")、角色单选(默认普通);确认后入列并 `ElMessage.success`。
- 空态:🔍 + "没有匹配的用户"(清空筛选按钮)。

### 5.3 系统日志(`/admin/logs`,只读)

- **统计行**:日志总数 / 今日(mockToday)条数 / 安全类条数。
- **筛选区**:模块 el-select + 类型 el-select + 关键词(摘要与操作人昵称)。
- **日志列表**(倒序):时间、操作人(头像 + 昵称)、模块 tag(中性)、类型 tag 着色(create=success / update=primary / delete=danger / login=info / security=warning)、摘要内容。**无操作列**——日志只读是审计语义,删除/导出列入未来规划。
- 空态:📭 + "没有符合条件的日志"。

## 6. 交互与视觉规范

- **新增身份色** `--app-admin: #64748b`(石板灰):tokens.css `:root` 定义,双主题通用,同 `--app-ledger` / `--app-notes` 惯例;灰调传达"系统/控制台"而非生活应用的彩色情绪。
- tag 语义色固定(见 §5.2 / §5.3);删除/停用等敏感操作一律 ElMessageBox 二次确认 + 成功 ElMessage;样式统一走 tokens 变量与 `.yiyu-card`,数字加 `.num`;大页面样式独立同名 `.css`(AdminDashboard.vue + AdminDashboard.css)。
- el-form 内的自绘按钮**必须显式 `type="button"`**(个人中心文档 §6 的既有教训)。
- 时间字符串统一 `YYYY-MM-DD HH:mm`,排序直接字符串比较;mock 日志日期硬编码 2026-09-01 ~ 09-07,禁止 `new Date()` 锚定。
