# AI 助手 · 需求设计

> 模块路径:平台级模块(非子应用,不进应用卡栅格);前端 `yiyu/src/modules/agent/`、后端 `yiyu-server/src/modules/agent/`。身份色 `--app-agent`(紫 #7c5cff)。
> 涉及代码:前端 `modules/agent/`(agent-stream.ts 流式层 / stores/agent.ts / components/ 悬浮球+抽屉 / chat-cards/ 注册表)+ `modules/ledger/chat-cards/` + `modules/profile/chat-cards/` + admin 三页(AdminAiConfig/AdminAgentSkills/AdminAgentUsage)。
> 联动改造:PortalLayout/AppShellLayout(挂 `<AgentFab/>`+admin 菜单 +3)、tokens.css(--app-agent)、admin/routes.ts、deploy/nginx.conf(SSE 关缓冲)、后端 schema.prisma(+5 表)、API契约.md/数据库设计.md。
> 现状:**已实现**(2026-09-12),前端 type-check/build 通过,后端 build 通过。LLM 真实联调待管理员在后台「AI 设置」配置端点后验证。

## 1. 产品定位

内嵌于系统的 AI 助手:可闲聊、可调用系统功能(查询/记账)。核心架构原则:**工具调用逻辑全在后端**,web 抽屉与未来移动端 App(打开即对话,以 agent 实现数据写入)共用同一套 `/api/agent/v1/` 契约——它是整个系统的"自然语言 API"。

一句话:子应用管"事",agent 是跨应用的统一入口。

## 2. 入口设计

- 全局悬浮球(✦):挂在 PortalLayout(广场)与 AppShellLayout(ledger/profile/admin 应用壳)两布局,登录态任意页面可见;点击开右侧 el-drawer(420px,append-to-body)。
- 登录页无悬浮球。未来 App 端直接呈现抽屉内的聊天主体。

## 3. 领域模型(后端 5 张新表,详见 yiyu-server/docs/数据库设计.md)

- **SystemConfig**:运行时 KV(`ai.llm`/`ai.persona`/`agent.settings`),apiKey 只存后端、回显脱敏尾 4 位。
- **AgentConversation / AgentMessage**:多会话结构;消息 role(user/assistant/tool)× kind(text/tool_calls/tool_result/confirm_card),content 为判别联合 JSON,seq 会话内单调递增作分页游标。
- **AgentSkillConfig**:技能启停覆盖(无记录=启用);技能本体在代码注册。
- **AgentUsageLog**:每次 LLM HTTP 调用一行(chat/summarize/test),仅统计不限额。

## 4. 技能体系(SkillRegistry)

- 技能声明 `{id, group, name, label, description, risk, parameters, preview?, handler}`;各业务模块在 OnModuleInit 注册(类似前端每模块导出 routes.ts 的约定),**新子应用接入即自动扩展 agent 能力,无需改 agent 代码**。
- 技能组三类:业务模块组(ledger/profile)、通用组(common,纯内置如日期计算)、未来外部扩展点(预留)。
- 风险三级:低=直接执行(查询类);中=确认卡→执行(记一笔/改备注);高=警告卡+风险提示→二次确认(删流水)。
- 确认卡是**消息流一部分**(非弹窗),10 分钟过期(惰性判定),同会话同时仅一张 pending 卡(新卡/新消息自动取代);App 端可直接复用同一交互。
- handler 直接函数调 LedgerService/UsersService/InviteCodesService(首参 userId,权限校验内聚),不走 HTTP 自调。
- 首期 8 技能:ledger 查流水/查报表(低)/记一笔(中)/改备注(中)/删流水(高)+ profile 查资料/查邀请码(低)+ common 日期计算(低)。记账分类由 LLM 从上下文分类树智能匹配(传名或 id,handler 内精确→模糊匹配)。

## 5. 对话循环与上下文

- Agent 循环:用户消息 → ContextBuilder 组装(system+窗口历史+技能清单)→ LLM(流式)→ tool_calls → 按风险执行或挂确认卡 → 结果回传 LLM → 直到最终回答;最大工具轮数可配(默认 6,末轮强制无工具总结收尾)。
- 混合上下文:最近 N 条(默认 20,可配)原文 + 更早消息滚动摘要(结构化键值文本,显式保留账本/分类偏好、金额、称呼;SSE 收尾后 fire-and-forget 压缩)。
- 数据实时性:每次数据问题都实时调 service 查询(每次现查,不信会话内旧数据)。
- 页面上下文感知:发送时携带 `{app, title, hint?}`(ledger 页注入当前账本名)。
- 轻主动开场:新建会话基于 portal summary 拼装一句(不调 LLM)。
- 流式:恒 stream:true;`ai.llm.streaming` 配置可关(个别网关 stream+tools 长尾时降级整段返回);流中坏帧跳过、usage 无返回按字符估算标 estimated。

## 6. SSE 协议(web 与未来 App 的共享契约)

事件:message_start / message_delta / message_end / tool_start / tool_result / confirm_required / usage / done / error / ping(15s)。流前错误=HTTP envelope,流中=error 事件。前端用原生 fetch+getReader(带 Bearer header,EventSource 做不到);nginx 已配 proxy_buffering off。契约全文见 yiyu-server/docs/API契约.md「agent」节。

## 7. 页面设计

- **抽屉聊天**(AgentChatPanel):头部(会话列表☰/新会话+/关闭)+ 消息流(用户右紫气泡/助手左灰气泡/工具结果行+卡片/确认卡)+ 输入区(快捷 chips「记一笔·本月总结·最近流水」+ textarea + 发送/停止切换)。降级态:LLM 未配置→顶部黄条提示,输入禁用。
- **聊天卡片注册表**(chat-cards/registry.ts):cardType→组件,聚合各业务模块 `chat-cards/index.ts`(镜像后端技能组);ledger 5 卡(流水表/报表含分类占比条/记账成功/改备注/删除)+ profile 2 卡(资料/邀请码)+ agent 内置(确认卡/JSON 兜底)。
- **后台三页**(admin 组,requiresAdmin):
  - AI 设置:LLM 连接(baseUrl/apiKey 脱敏占位/model/流式开关/测试连通)+ 人设 textarea + 行为参数(总开关/窗口条数/工具轮数)。
  - 技能管理:按技能组分组,风险 el-tag(低绿/中橙/高红)+ 参数 schema popover + 启停 switch(乐观更新失败回滚);风险等级代码声明不可改。
  - AI 用量:统计四格(调用/输入/输出/合计 tokens)+ 每日调用柱状 + 按用户表;时间筛选(今天/近7天/近30天);**仅统计不见对话内容**。

## 8. 交互与视觉规范

- 身份色 --app-agent(#7c5cff):悬浮球/用户气泡/快捷 chips/用量柱。
- 确认卡:中风险橙边框、高风险红边框+warning 文案+「确认执行(高风险)」红按钮;倒计时 mm:ss;终态(已执行/已取消/过期)就地保留在消息流。
- 金额红支出绿收入语义不变;数字 .num 类;卡片 .yiyu-card。

## 9. 安全与审计

- 后端以当前登录用户身份调 service(传 user.id),非 admin 永远碰不到 admin 能力;apiKey 只存后端。
- agent 写操作审计 module='agent'(与业务 service 自身 ledger 审计**双写**);AI 配置修改 action=security 语义(update)。
- 对话内容明文存 PG,后台 UI 不可见;用量按用户聚合。
