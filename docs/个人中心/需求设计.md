# 个人中心 · 需求设计

> 模块路径:`/profile`,入口:顶栏头像下拉「个人中心」;**平台级用户模块而非子应用**,不设独立身份色
> 涉及代码:`src/modules/profile/` —— `types.ts`(Profile)、`mock/profile.ts`、`stores/profile.ts`、`routes.ts`(`profileRoutes`)、`views/ProfileInfo.vue`
> 联动改造:`shared/layouts/AppShellLayout.vue`、`shared/layouts/PortalLayout.vue`、`router/index.ts`、`shared/stores/user.ts`、`shared/types/common.ts`、`shared/types/router.d.ts`;**`modules/settings/` 已整体移除**(修改密码并入基本信息);**广场个人名片已移除**(2026-09-10)
> 现状:**已实现**,`pnpm type-check` 通过。文中按当前实现描述。

## 1. 产品定位

个人中心是一隅的**平台级用户模块**(而非与记账本并列的子应用):维护当前登录人的个人档案。档案是全站的**共享基础数据**——广场问候与顶栏头像取档案的昵称/头像。

一句话:个人中心管"我",子应用管"事"。

## 2. 入口设计

- **广场个人名片已移除(2026-09-10)**:PortalHome 问候区不再放个人名片卡,入口收敛,广场只保留问候与应用卡。
- **顶栏头像下拉**(PortalLayout 与 AppShellLayout 两处):「个人中心」(→ `/profile`)+「退出登录」。
- **settings 模块已整体移除**:修改密码并入基本信息页右列;外观深浅色切换走顶栏日/月图标按钮;退出登录走头像下拉。

## 3. 领域模型

### 3.1 个人档案(Profile)

| 字段 | 说明 |
|---|---|
| `id` / `username` | 用户标识与登录名,**只读**(mock 登录固定 `u1`) |
| `nickname` | 昵称,必填 ≤12 字,全站展示名 |
| `avatar` | 头像 emoji,固定 12 选 1:`🧑‍💻👩👨‍🦰👩‍🦳🧕🐱🐰🦊🐻🌻☘️🌙`,不做图片上传 |
| `bio` | 个性签名,≤30 字,可选 |
| `gender` | 性别:`secret` 保密 / `male` 男 / `female` 女 |
| `birthday` | 生日,日期,可选 |
| `region` | 所在地区,文本输入 ≤20 字(如"四川·成都"),可选 |
| `updatedAt` | 最近更新 `YYYY-MM-DD HH:mm` |

- 类型落点:`shared/types/common.ts` 的 `User` 接口含可选 `avatar`(兼容旧登录态;缺省按 🧑‍💻 展示)。档案其余字段定义在 `modules/profile/types.ts`,不进 `User`——`yiyu-user` 只持久化登录态所需最小集。
- 档案是 `yiyu-user` 登录态的扩展:登录时以 `{ id, username, nickname }` 初始化档案;`userStore.updateProfile` 签名收窄为 `Partial<Pick<User, 'nickname' | 'avatar'>>`,昵称/头像同步写回 `yiyu-user`(localStorage 持久化),保证刷新后顶栏、广场问候不回退;其余字段遵循全局约定刷新重置。`updateProfile` 的实际落点是 profile store,由它转调 userStore。
- `login()` 覆写 `yiyu-user` 时**保留已有 avatar**(重新登录不丢已选头像)。
- 性别/生日/地区仅存档,当前无展示面,预留给后续能力(见 §6)。

### 3.2 好友(已移除)

**好友功能已整体移除(2026-09-10)**:Friend / PendingRequest / CandidateUser 类型、好友 mock、ProfileFriends 页面与路由均已删除,与账本协同(成员/邀请)一并简化。档案是个人中心仅剩的领域数据。

## 4. 页面设计

### 4.1 基本信息(`/profile/info`,默认页)

路由:`/profile` → redirect `/profile/info`;meta `{ app: 'profile', title: '基本信息', requiresAuth: true }`。

- **名片头卡**:大头像(emoji,56px 渐变底)+ 昵称 + 签名;统计行(`.num`):已加入 126 天(mock 固定,沿用现有文案)。「账本 N 本」统计已移除(2026-09-10),个人中心不再跨模块消费 ledger store。
- **资料编辑卡**(左列):头像 emoji 宫格选择(选中态描边,复用 Books 图标选择样式)、昵称(必填 ≤12,show-word-limit)、签名(textarea ≤30)、性别单选(保密/男/女)、生日(date-picker,可清空)、地区(文本 ≤20);「保存资料」写回 store,toast「资料已更新」,昵称/头像即时反映到顶栏与广场问候。
- **右列堆叠**:账号只读卡(用户名、用户 id,灰字"注册后不可修改")+ **修改密码卡**(自原设置页迁入:当前密码/新密码/确认新密码,校验 ≥6 位且两次一致,mock 仅提示成功后清空表单)。

壳层菜单(AppShellLayout 的 `apps` 含 `profile` 组):**基本信息(elIcon `User`)**,菜单随 `meta.app` 自动切换;组色走中性 `--text-secondary`,顶栏徽标图标 👤、名称「个人中心」、副标题「我是谁,与谁同行」。

## 5. 与子应用的共享约定

- **唯一数据源**:`modules/profile/stores/profile.ts`(`useProfileStore`)导出 `profile`(档案)与 `updateProfile`;子应用**不得各自维护用户资料副本**。仍遵守 CLAUDE.md 约定不跨模块 import 别人的 views/mock。
- **广场联动**:问候昵称/头像消费档案数据(顶栏头像同步);广场个人名片(含账本数统计)已移除,无其他消费点。
- **数据边界**:档案不持久化,刷新重置为 mock 初始值(昵称/头像除外,见 §3.1);时间字符串统一 `YYYY-MM-DD HH:mm`,mock 基准日沿用 `shared/types/common.ts` 的 `mockToday`(2026-09-07),不得使用 `new Date()`——`updateProfile` 写入的 `updatedAt` 为硬编码字符串。

## 6. 交互与视觉规范

- **不新增身份色**:个人中心是用户模块而非子应用,壳层与入口视觉走中性色(`--text-secondary` 系),头像沿用既有渐变;未改 tokens.css。
- 头像体系:**emoji 头像**,不引入图片上传与对象存储。
- 样式统一走 tokens 变量与 `.yiyu-card` / `.yiyu-card--hover`,数字加 `.num`;窄屏(<768px)基本信息双列降单列并隐藏头卡统计行。
- **el-form 内的裸 `<button>` 必须显式 `type="button"`**(头像宫格、图标宫格等):HTML 规范中 form 内 button 缺省 `type="submit"`,缺省会触发表单提交导致页面原生导航跳转。实现期曾因此出过 bug(URL 出现 `?el-id-*=secret` 查询串),ProfileInfo 头像宫格与 Transactions 自定义分类图标宫格均已补 `type="button"`。
